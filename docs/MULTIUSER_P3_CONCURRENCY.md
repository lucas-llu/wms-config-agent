## 第一批：持久任务与接口底座

- `002_durable_runs.sql` 在 P1 之后独立迁移；不在普通 API 启动时执行 DDL。
  合成测试迁移器带版本与校验和，重复执行不重复创建表；运行角色仍不拥有表、不绕过 RLS。
- runs / run_events / run_outbox 按归属和父对话执行 RLS；已删除、非本人、成员撤销的资源不能使用。
  所有方法使用当前可信 `UserContext`，不接受请求的 owner、roles 或 checkpoint 标识。
- 同用户、对话、幂等键重复提交返回已有任务；内容、策略、预期版本改变返回冲突。
  回放先于版本检查，因此已完成任务推进版本后仍能安全重试原请求。
- 同一对话最多一个 queued / running / cancelling；用户入队与 claim 用数据库账号锁串行核对上限。
  默认待处理 5、运行 2，可配置；这不是 P4 的 token/费用额度预留。
- 接收任务与 outbox 同事务。派发确认绑定 delivery_id，旧确认不能覆盖恢复后新投递。
  outbox 只导出 run_id 与 delivery_id，不包含消息、token、工具名或知识库正文。
- claim 生成服务端执行代次与独立 checkpoint thread；心跳、进度、模型调用标记和完成均检查有效租约。
  取消阻止下一步与迟到写入；完成回调、业务版本/答案、终态事件使用同一短事务。
  回调只允许已校验结果持久化，不得进行模型/检索等长调用，完成前再次核对租约。
- 模型已发出但结果未知的过期任务标记 uncertain，不盲目重发；取消不声称已发送调用零费用。
  已收到模型结果但未完成业务提交的过期任务标记 recovery_required，等待可信检查点承接，
  在完整承接接通之前同样不从头重跑。持久 attempt 数与未返回调用数分别保存。
  安全恢复目前仅覆盖未进入模型的存储阶段；完整图节点/检查点承接属于下一批。
- 进度为持久递增事件，包含阶段和已提交版本指针，不输出未校验模型正文。
  SSE 游标绑定 run_id，分页补读不重新提交任务；每批检查 IdP 和数据库授权。
  单个连接最长 20 秒，空闲心跳，终态结束；后续 React 客户端负责携带 Bearer 重连。
- 回收站永久删除覆盖该对话所有 checkpoint thread，包括新增代次；不会遗留代次检查点。

新增 API 仅由显式 `run_limits` 参数启用，测试环境使用。
生产 `api.bootstrap.from_environment` **尚未启用**，React 也仍使用 P2 同步路径，
因此当前没有“接受了后台任务但实际上无人处理”的公开功能。

## 后续两批及明确缺口

1. 执行与调度：接通固定 RQ JSONSerializer 作业入口、周期 outbox 派发和恢复器；
   Worker 只收到 run_id；授权上下文由服务端重新取得并检查 Keycloak SID 的当前有效性，
   不能把原请求 lambda 或 bearer 存入任务。身份服务不可用时停止执行，不能只凭旧 JWT 快照。
   统一模型入口的全局在途/RPM/TPM、旁路子上限、每用户公平轮转与有界退避。
   共享只读检索服务避免每个 RQ 子进程重新加载索引，连接池按全部进程总量规划。
   图节点代次隔离与可信快照承接，结果只通过持久租约检查的短事务提交。
2. 前端与故障验收：React 202 接收、排队/检索/生成/核验、取消、刷新查询活跃任务、
   带 run 游标的 SSE 重连和明确不确定状态；同消息刷新不重复执行。
   真实 Worker 硬中断、Redis 重启、PG 失联、多标签页、取消与成员/设备撤销故障测试。
   供应商约束未确认前仅做合成 1/2/5/10/20 档验证，不把它冒充 P5 真实模型并发门禁。

P4 仍负责真实逐 attempt 用量、价格版本、月额度预留/结算及未知费用对账。
P5 仍负责正式 SMTP/HTTPS、旧数据归属迁移/回退、真实压力报告和灰度开放。
